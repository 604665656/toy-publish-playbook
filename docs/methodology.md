# 审核黑盒下的区间二分定位法

适用：平台只回「内容审核未通过」、不给命中词、不提供申诉细节，但你必须在不删光内容的前提下过审。

本次实测：**7 轮盲改全部失败 → 建立二元判据 → 25 个并行探针 → 一轮锁定 5 段 → 改一次即过审。**

---

## 0. 先别改任何东西，建立「二元判据」

平台返回里找一个**稳定、可机器判定的信号**，而不是 `status`。

本次用的是 `audit_failures` 是否包含 `{type:'content', reason:'rejected'}`：

| 返回 | 含义 |
| --- | --- |
| `status=rejected`，`reject_reason=内容审核未通过`，有 `audit_failures` 的 content 项 | 内容扫描**命中** |
| `status=rejected`，`reject_reason=审核未通过`，**无** `audit_failures` | 内容扫描**已放行**，倒在功能/其它关卡 |
| `status=published` | 全过 |

> 这一条是整个过程的分水岭。之前把「审核未通过」也当成同一类失败，导致所有实验结论都是噪声。

也不要用 `poster_url` / `icon_url` / `watermark_enabled` 判断上传是否成功——这些字段只在发布成功后回填。

---

## 1. A/B 对照，先排除所有非内容变量

**同一账号、同一封面、同一图标、同一水印开关、同一分类、甚至同一标题**，只把页面换成一个 1KB 的极简页面提交。

- 极简页 `published` → 账号权限、素材、元数据、提交参数全部无罪，问题在内容。
- 极简页仍被拒 → 问题在元数据/账号/素材，别去改内容。

再把标题单独改回原名复测一次，把标题也排除掉。**一次只动一个变量，但要把变量清单排干净。**

---

## 2. 等长中性化，把「内容」拆成模块

对候选数据做**逐字等长替换**（CJK → 「文」）：

```python
re.sub(r'[\u4e00-\u9fff]', '文', s)
```

要点：

- **长度 1:1 不变**，JSON 结构、数组长度、字段全不变 → 运行时数据自检的长度校验照样能过。
- 只消掉语义，不动代码路径，页面仍能完整渲染（只是文字全是「文」）。
- 若自检里有「末条字符串包含 XX」这类内容断言会失败，探针包里临时去掉启动阻断即可。
- **务必用真实浏览器确认探针包确实渲染了**。如果它是白屏，那么「内容关已过」的结论就不成立（可能是审核方根本没读到内容）。

按顶层数据模块逐个中性化，找到「全中性化才放行」的最小模块集合。本次结论：三十个模块里只有 `civilization` / `peoples` / `reading_quiz` 三册有关，其余 20 个模块和页面代码字符串全部清白。

---

## 3. 用「恢复式区间探针」，而不是「屏蔽一半」

普通二分在**多个触发源分散**时会失效：屏蔽 A 半，B 半里还有触发点 → 仍命中；屏蔽 B 半，A 半里还有 → 也命中，两边都失败，无法收敛。

正确做法是把因果反过来：

```
先把所有候选模块全中性化（已知内容关会放行）
再只把全局序号 [a,b) 的条目「恢复原文」
→ 该区间一旦命中，证明它至少含一个触发点
```

这样每个探针只负责回答「这一小段里有没有雷」，多个雷并存也不影响。

---

## 4. 并行提交，把审核轮次压缩成 1 轮

审核是异步且彼此独立的，一轮约 100–170 秒。**不要串行试。**

```bash
for i in 0 1 2 3 4 5 6 7; do
  toy create probe_p$i --slug "probe$i" --visibility link-only \
      --watermark --poster cover.png --icon icon.png --yes --json
done
sleep 210
toy mylist --json | python read_results.py
```

- 每个探针给唯一 slug，`visibility=link-only` 避免污染公开列表。
- 用标题编码区间编号（如 `区间探针P3`），方便 `mylist` 里对号入座。
- 一次读全部 `audit_failures`，哪几段命中一目了然。

**注意平台每日 `create` 上限**：触顶会返回 `-509 今日创建数量已达上限，请明天再试`。此时改为复用已有 Toy：

```bash
toy update <已存在的id> probe_dir --yes --json
```

`update` 不受创建数限制，可以无限轮次继续切分。本次用了 P0–P7、Q0–Q4、R0–R11 共 **25 个窗口**，从 4132 条收敛到 799 条。

---

## 5. 收敛后只改一次

把命中的最小区间从构建产物里移除（或改成合规内容），其余文本全部保留原文，然后一次性提交。

本次：4132 条里移除 799 条（19%），保留 3333 条（81%）真实文本 → 直接 `published`。

**不要顺手再做别的「保险处理」**，否则无法确认是哪一步起了作用。

---

## 6. 本地分析只用来生成假设，不用来下结论

对命中区/干净区做 n-gram 差分、敏感词表扫描，能帮忙缩小候选，但本次捞出来的高频串多是「通识级锚点」「不作学术引用」这类无害样板句。**是否真的命中，一律以平台 `audit_failures` 为准。**

同理，词面替换（本次试了 40 组）对语义级审核无效——别在这上面耗轮次。

---

## 反模式清单

- ❌ 看到 `poster_url` 为空就重做封面
- ❌ 靠「换个更安全的说法」逐轮猜敏感词
- ❌ 串行一次只提交一个版本
- ❌ 把 `审核未通过` 和 `内容审核未通过` 当成同一种失败
- ❌ 用无头浏览器的空 DOM 快照判定白屏
- ❌ 一次提交里同时改五处，过了也不知道是哪处起效
